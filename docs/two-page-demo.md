# 两页饮食体验

## 使用

启动命令不变：`powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-demo.ps1`。
访问 http://127.0.0.1:8000/，已有页面按 Ctrl+F5 刷新。

第一页录入年龄、身高、体重、疾病、药品，以及可选过敏信息和饮食偏好。默认虚拟示例：42 岁、172 cm、82 kg，BMI 27.72，血脂异常和脂肪肝；药品留空，不编造处方。可添加实际药品的名称、通用名、剂量、时刻和进餐关系。

第二页有两个页签：

- 饮食指南：由多疾病规则合并，显示共同重点及来源；用户记录的药物如命中药食规则，会单独提醒。
- 记录饮食 / 查看评分：逐项记录早餐、午餐、晚餐、加餐及饮品的食物和份量，可载入两份虚拟饮食示例。勾选全天完整记录后保存，即可查看每项分数和调整方向。

重复保存同一患者同一天的记录会更新该日记录。刷新浏览器后可恢复最近资料和保存的当天饮食；最近 30 条记录可按日期载入。修改资料后，旧评分保留当时的资料快照，需要再次保存饮食才会重新计算。

## 评分边界与来源

六项指标：蔬菜、全谷物、蛋白质食物、含糖饮品与甜食、油炸及高脂食物、酒精。患者疾病只改变显式配置的演示权重。总分 = 各项得分之和 / 权重之和 × 100。

权重和份数阈值由本演示产品设计，不是医学量表，不是临床处方，也不是指南认可的评分公式。食物份量为近似录入参照；不估算热量或营养素克数，不判定营养足量或治疗效果。所有食品只是少量分类词典，备注不自动解析。未识别食品、未完成记录、完全没有食物记录和未成年人不输出总分。没有记录到酒精或甜食仅在用户确认全天完整记录后才用于计分。

饮食方向参考 [NIDDK 脂肪肝饮食资料](https://www.niddk.nih.gov/health-information/liver-disease/nafld-nash/eating-diet-nutrition)、[NHLBI 血脂生活方式指导](https://www.nhlbi.nih.gov/health/TLC-Therapeutic-Lifestyle-Changes-Lower-Cholesterol) 和 [NHLBI 心脏健康饮食](https://www.nhlbi.nih.gov/health/heart-healthy-living/healthy-foods)。这些来源支持一般饮食方向，不为演示分数背书。脂肪肝类型与是否需要完全戒酒由医生确认，系统不设安全饮酒量。

## 实现

- `backend/app/diet_routes.py`：原子资料保存、指南、按日期保存/读取饮食记录。
- `backend/app/diet_schemas.py`：食物、份量、餐次状态和日期校验。
- `core/nutrition/scoring.py`：确定性评分，无 LLM 或外部 API。
- `data/rules/diet_score_rules.json`：版本化规则、计算方式与来源。
- `data/foods/diet_catalog.json`：家常食物分类字典。
- `backend/app/static/{index.html,app.css,app.js}`：两页交互及响应式布局。
- 新增 `diet_logs` 表；保留现有表和记录，不执行删除或重建数据库。

## 验证

全部 36 项 pytest 测试通过，另有一条既有第三方弃用提示。后端测试覆盖：脂肪肝约束合并、资料修改不重复、非法输入不落库、药物归属、完整/不完整记录、未知食物不评分、持久化、同日覆盖、未来日期拒绝。

隔离数据库下的真实 Chrome 流程通过：生成指南、保存不完整记录、完整评分、对比示例、刷新恢复、未识别食物处理、修改资料和药物并触发相关提醒。42 岁/172 cm/82 kg 的默认示例中，待改善饮食为 38 分，调整后为 100 分（仅满足六项演示规则，非医学评价）。

1440px 桌面及 390px 手机宽度截图已检查，手机无横向溢出。浏览器测试没有页面 JavaScript 异常、没有外部资源请求。测试使用独立数据库，未改动用户的现有记录。

仍是本地浏览器 MVP，Flutter 手机端未初始化。无需外部服务器，服务仅监听 127.0.0.1。
